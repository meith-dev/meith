# Upgrade compatibility

Use [Upgrade a board](upgrading.md) for the procedure. These notes cover behaviour changes in the 0.x series; review stored settings before upgrading an older board.

## Defaults and configuration

| Change | Action |
|---|---|
| `reputation.comment_required` defaults off | Re-enable to require rating comments and remove one-click Thanks |
| Navigation defaults to Home, New posts, Search | Re-enable other entries under Content → Navigation; migration hides only untouched rows |
| `TRUSTED_PROXY_HOPS` defaults to 0 | Set the actual trusted proxy count; the generated by-hand stack defaults to 1 |
| Mail can be saved in the panel | Explicit HTTP/SMTP environment config still wins; test delivery |
| Board address can be saved in the panel | `APP_URL` still wins |
| SMTP driver is implemented | Set sender, relay and security/authentication fields |
| `TICK_DEADLINE_MS`, `TICK_MAX_JOBS` removed | Remove unused variables |

Defaults affect settings without stored overrides.

## Newly enforced settings

| Setting | Current behaviour |
|---|---|
| `posting.edit_grace_seconds` | Default 300; suppresses new edit notices for timely self-edits, not moderator edits or revision history |
| `search.min_word_length` | Default 2; at least one word must meet it |
| `search.enabled` | Disables navigation, page and API search; maintains the index |
| `registration.enabled` | Disables public form and POST; installer/CLI creation remain available |
| `registration.method` | Enforces none, email, admin or both; default none preserves former behaviour |
| Password minimum | Default 10 for new passwords; existing passwords remain valid |
| Username bounds | Default 3–30 code points; invalid min/max pair falls back to these defaults |
| Session/lockout settings | Enforced; default session 14 days and account-wide attempt limit 50 |
| `maxPostsPerDay` | Threads and replies share a UTC-day allowance across forms/API |
| `maxPrivateMessagesPerDay` | Daily sends; separate from stored-message quota |

A former email-activation choice equal to the old default may have no stored row. Configure working mail, then explicitly select email activation if required. Daily caps use zero unlimited; flood bypass does not lift them.

Registration/reset/address-login limits now default to 10 registrations/hour, 5 resets/email/hour, 20 resets/address-range/hour and 100 login failures/window. Review shared-network impact under [Antispam](../administration/antispam.md).

## Permissions

- Restore now requires **Restore posts**. A migration grants it to existing delete-capable appointments; new appointments need both selected when intended.
- Inert **Delete permanently**, **Manage polls** and **See posters' addresses** moderator fields were removed.
- `canDeleteOwnThreads` now permits reversible whole-thread deletion, including replies; it defaults off.
- Migration 0042 removes unused `canDeleteOthersPosts`; actual reversible moderation uses `canSoftDeletePosts`. Groups carrying only the removed field no longer count as powerful.

## `meith migrate` decides by hash, not by timestamp

Boards upgraded from 0.29.0–0.31.x to 0.32.0, 0.33.0 or 0.33.1 can lack migrations 0062–0065 because earlier journal timestamps were out of order. Fresh installs and upgrades from 0.28 or earlier are unaffected.

Symptoms include missing `u.board_digest_cadence`, feed-token, auto-watch or report-category columns despite an up-to-date version notice. Upgrade to a release with the hash-based runner and run `meith migrate`. It applies missing hashes in journal order. The current panel checks missing migrations where files are available and refuses to record a version over a stale schema.

## Data and display

| Change | Action |
|---|---|
| Bundled PostgreSQL 16 → 18 | Perform a separate database major upgrade; do not reuse the old volume with the new image |
| `meith backup` / `restore` | Use bundles with uploads and explicit empty restore targets |
| Post anchors use number | Themes use `post-<post.number>`; durable links use `?post=<id>`; old ID fragments may land differently |
| Delete/restore notices | Use `?removed=post` and `?unchanged=post` |
| Category pages/threads | Categories now render; thread creation remains opt-in |
| Automatic timezone | Former UTC defaults move to browser detection; members wanting UTC must select it explicitly |
| Plugin upgrades | `meith upgrade` reads installed plugin definitions and applies their migrations |
| Editable navigation | Render optional `newTab` and one-level `submenu`; preserve no-JavaScript access |

See [Theme compatibility](../extensions/theme-contract.md#versioning) for model changes.

## Replace the old webhooks plugin

Core webhooks replace `@meith/plugin-webhooks`; settings are not migrated automatically.

1. Create a subscription under **Admin → Webhooks** with the old endpoint and payload format.
2. Select `thread.created` and, if needed, `post.created`.
3. Save the new signing secret in the receiver.
4. Change receiver headers from `x-meith-*` to `x-forum-event`, `x-forum-delivery`, `x-forum-timestamp` and `x-forum-signature`.
5. Verify delivery, then remove the old plugin and `WEBHOOKS_*` variables.

HMAC material remains `<timestamp>.<raw body>`. Core uses the configured board origin and sends Discord content links rather than the old rich embed. See [Webhooks](../integrations/webhooks.md).
