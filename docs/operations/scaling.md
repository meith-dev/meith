# Multiple web instances

All instances must share PostgreSQL, cache and uploads. Sessions, core flood limits, queues and task claims are database-backed; sticky sessions are unnecessary. Plugin route limits are process-local and multiply across replicas.

## Prepare shared services

1. Configure `CACHE_DRIVER=redis` and `REDIS_URL`.
2. Back up uploads and copy them to shared storage, preserving keys. Use a shared volume on one host or S3-compatible storage across hosts.
3. Set the file-store environment and restart the existing instance.
4. Verify old files, a new upload and settings before adding replicas.

Changing drivers does not copy data. Keep original uploads until verified. Redis is not the durable source, but an unavailable configured cache can fail requests.

## Add replicas

Adapt the proxy to route on the service network and remove fixed host-port bindings before scaling. Then, for the generated by-hand stack:

```sh
docker compose --profile redis up -d --build
docker compose --profile redis up -d --scale web=3
```

Set `TRUSTED_PROXY_HOPS` to proxy count, not replica count.

Each process opens its own database pool. Include replicas, workers and maintenance in the [connection budget](database-operations.md).

Verify a setting change and upload across different instances, sign-in and private content. Aggregate [per-process metrics](monitoring.md) and monitor queue progress.
